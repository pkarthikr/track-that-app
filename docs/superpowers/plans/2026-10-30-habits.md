# Habits and Completions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A signed-in user creates habits, logs and undoes completions per day, sees a streak per habit, a calendar-week grid on Home, and a 365-day heatmap on a detail screen, all stored in DynamoDB behind an HTTP API.

**Architecture:** Pure domain logic (dates, streak) in `packages/core`, shared types and validators in `packages/shared`, a single Lambda behind an HTTP API with a Cognito JWT authorizer in `services/api` and `infra`, and a typed habits client plus three screens in `apps/web`. One DynamoDB table holds habits and completions in a per-user partition.

**Tech Stack:** TypeScript (strict), Vitest, React 19 + react-router 8, AWS CDK 2 (`aws-cdk-lib`), DynamoDB (`@aws-sdk/lib-dynamodb`), esbuild, `aws-amplify` (token only).

**Spec:** `docs/superpowers/specs/2026-10-30-habits-design.md`

## Global Constraints

- Table keys: habit `PK=USER#<sub>`, `SK=HABIT#<ulid>`; completion `PK=USER#<sub>`, `SK=COMP#<habitId>#<yyyy-mm-dd>`. The user id is the verified `sub` claim, never anything from the request.
- Weekdays are integers 0 to 6, Sunday first, matching `WeekRow`. Weekdays are immutable after creation.
- Name is 1 to 60 characters after trimming. Colors are exactly `green, teal, blue, violet, pink, coral, orange`.
- At most 50 habits per user, archived ones included (`MAX_HABITS`). Completion dates: at most 1 day after the server's UTC date, at most 366 days before it.
- Streak: consecutive scheduled days, rest days neither break nor extend it, completions on unscheduled days ignored, an unfinished scheduled `today` does not break it, no completions means 0.
- Dates are `yyyy-mm-dd` strings; all date arithmetic is UTC-based and never uses the local time zone.
- Table: on-demand, point-in-time recovery on, `RETAIN`. Lambda runtime `nodejs22.x`, granted read and write on that table only. CORS allows any origin (bearer token, no cookies).
- Nothing is deployed by this plan. Never run `cdk deploy`, `aws`, `gh variable set` or the Deploy workflow.
- Match the surrounding code: Prettier config in `.prettierrc.json`, tests beside source as `*.test.ts(x)`, `import type` for types (`verbatimModuleSyntax`), no inline styles or scripts in the web app (CSP).
- Commit messages end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.

## Review Focus

- A scheduled habit with a completion only on an unscheduled day, or `today` scheduled but unfinished: streak must not reset or inflate (Task 2).
- Garbage input to every route: non-JSON body, `null`, `[]`, 61-character name, weekday 7, `today=2026-02-30`, date `2026-13-01`: always a 4xx with a `code`, never a 500 (Tasks 4, 5).
- Another user's habit id on get, patch, put and delete: 404, and nothing written under either user (Tasks 4, 5).
- Date edges: Feb 29, the week spanning Dec 28 to Jan 3, a streak crossing a year boundary, weeks starting on a Sunday (Task 2).
- Failed writes and loads in the UI: a failed tick rolls back and shows an alert, a pending row ignores a second click, a failed load offers a retry (Task 9).
